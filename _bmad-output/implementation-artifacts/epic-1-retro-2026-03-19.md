## Difficultés et enseignements

### 1. @base-ui/react ≠ Radix UI

**Problème :** shadcn/ui v4 a migré de Radix UI vers @base-ui/react. Le prop `asChild` n'existe plus — il faut utiliser `render` prop à la place. Découvert lors du build en story 1.3.

**Leçon :** Le pattern `render` prop est le standard pour tous les composants @base-ui/react. Documenté dans les Debug Log de la story 1.3 et référencé comme intelligence pour les futures stories.

### 2. Next.js 16 strict sur Server/Client

**Problème :** `force-static` incompatible avec Sanity Studio (React contexts non disponibles au build SSG). Les metadata `export const metadata` ne peuvent pas cohabiter avec `'use client'` dans le même fichier.

**Solution :** `'use client'` sur la page Studio + layout séparé pour les metadata. Documenté en story 1.2.

### 3. Sanity client crash sans projectId

**Problème :** `createClient()` de Sanity throw quand `NEXT_PUBLIC_SANITY_PROJECT_ID` est vide, cassant le build entier.

**Solution :** Import dynamique conditionnel — vérifier que projectId existe avant d'importer le client. Fallback sur valeurs hardcodées sinon. Documenté en story 1.3.

### 4. Zéro tests automatisés

**Constat :** Acceptable pour le MVP (per architecture doc), mais risque croissant avec l'empilement de composants. À surveiller — si régressions en Epic 2, on ajoute des tests.
