## Difficultés et enseignements

### 1. Tests automatisés toujours absents

**Problème :** Engagement pris en Epic 1 ("surveiller, réévaluer en Epic 2") jamais adressé. 11 pages, 15+ composants, 3 composants embed avec state management, zéro tests.

**Leçon :** Le build + lint ne remplacent pas les tests. Le risque croît avec la complexité. À adresser impérativement avant l'Epic 4 (routes dynamiques blog).

### 2. Docs de planification contaminées par `asChild`

**Problème :** L'architecture et l'UX spec référencent `asChild` (Radix UI) alors que le projet utilise `render` prop (@base-ui/react). L'intelligence des stories corrige au runtime, mais crée de la confusion initiale.

**Leçon :** Les docs de planification doivent être mises à jour quand une découverte technique les invalide.

### 3. Pas de retro Epic 2

**Problème :** On a foncé directement de l'Epic 2 vers l'Epic 3 sans retro. Les leçons de l'Epic 2 ont été absorbées tardivement.

**Leçon :** Retros systématiques après chaque epic, même si le rythme est rapide.

### 4. Pas de pattern centralisé pour fetch Sanity + generateMetadata

**Problème :** La page contact fait un double fetch Sanity (generateMetadata + page). Next.js peut dédupliquer, mais pas de pattern formalisé pour les pages avec contenu Sanity.

**Leçon :** Pattern acceptable pour le MVP, mais à surveiller si d'autres pages Sanity sont ajoutées (blog).
