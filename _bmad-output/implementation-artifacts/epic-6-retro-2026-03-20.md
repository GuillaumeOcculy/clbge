## Difficultés et enseignements

### 1. Engagement tests E2E non respecté

**Problème :** L'engagement de la retro Epic 5 ("chaque story livrée avec ses tests E2E") n'a pas été tenu. Les stories 6.1 et 6.2 n'ont ajouté aucun test Playwright automatisé.

**Cause :** L'engagement était formulé pour des stories UI classiques. Les stories de configuration SEO (sitemap, robots.txt, JSON-LD, Google Analytics) n'ont pas déclenché le réflexe de tester.

**Leçon :** Les artefacts SEO sont observables dans le navigateur (XML, meta tags, JSON-LD dans le DOM) et doivent être testés. L'engagement est reformulé : "toute story avec des effets observables dans le navigateur est livrée avec ses tests E2E".

**Action :** Écrire `tests/seo.spec.ts` (action item #3).

### 2. Alignement visuel négligé

**Problème :** Des écarts visuels existent entre la maquette HTML (`ux-design-directions.html`) et le rendu final. Exemple : les liens de navigation du header apparaissent comme des boutons avec background au lieu de simples liens texte.

**Cause :** Aucun processus de vérification visuelle vs maquette n'existait. Les code reviews vérifiaient la qualité du code, les tests E2E la présence des éléments, mais personne ne comparait le rendu à la maquette.

**Leçon :** La fidélité visuelle doit être un critère de done explicite pour toute story touchant l'UI.

**Action :** Quick spec d'alignement visuel + assets réels (action item #1). Nouvel accord d'équipe ajouté.

### 3. Assets réels non intégrés

**Problème :** Les photos de Laurent (`Photo_profil_1.jpg`, `Photo_profil_2.jpg`) et le logo (`LOGO CLB GEOMÈTRE-EXPERT.jpeg`) sont disponibles dans `documents/` depuis le début du projet mais n'ont jamais été intégrés.

**Action :** Inclus dans le quick spec d'alignement visuel.
