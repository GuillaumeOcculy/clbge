## Difficultés et enseignements

### 1. Intégrations profondes = bugs de configuration invisibles

**Problème :** La story 4.2 a rencontré 3 bugs post-implémentation — `basePath: '/studio'` manquant, CSP bloquant les WebSocket Sanity (`wss://*.sanity.io`, `https://sanity-cdn.com`), et `images.remotePatterns` non configuré pour `cdn.sanity.io`. Aucun de ces problèmes n'est détectable par build ou lint.

**Leçon :** Les intégrations tierces profondes (Presentation Tool, iframe Studio/site, draft mode) génèrent des bugs de configuration que seul un test en navigateur réel peut détecter. C'est fondamentalement différent des embeds simples (Tally, Zcal) des Epics précédents.

### 2. Tests automatisés toujours absents — 3ème report consécutif

**Problème :** Engagement pris en Epic 1, reporté en Epic 2+3, ignoré en Epic 4. 14 pages, 20+ composants, des API routes, du draft mode, zéro tests.

**Leçon :** Le report systématique crée un pattern dangereux. Plus le codebase grandit, plus le risque de régression augmente. Décision prise : Epic 5 dédié aux tests E2E (Playwright).

### 3. Pas de test en environnement prod/staging

**Problème :** Les 3 bugs de la 4.2 ont été découverts en test local. Le draft mode, les cookies, les API routes et la communication iframe/Studio peuvent se comporter différemment sur Vercel.

**Leçon :** Un déploiement staging + test manuel est nécessaire avant de considérer l'epic terminé, surtout pour les fonctionnalités impliquant des intégrations serveur.
